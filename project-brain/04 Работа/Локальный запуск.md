## Бэкенд

```bash
cd platform
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]" -c requirements.lock
cp .env.example .env        # заменить каждый CHANGE_ME_*
docker compose -f infra/compose/compose.yaml --env-file .env up -d --wait
curl http://127.0.0.1:8000/health/ready
```

Тесты — по `platform/README.md`:

```bash
docker compose --profile test --env-file .env -f infra/compose/compose.yaml run --rm db-tests \
  pytest -q --tb=line -p no:cacheprovider tests/unit tests/integration tests/security tests/contract
```

Используйте изолированные имена Compose-проектов и не удаляйте чужие тома. Живые тесты провайдера M08 запускаются только через отдельный гейт.

## Вход в приложение локально (настроено 15.11.2026)

Стек `retail_ops_local` в Docker: Postgres, Redis, MinIO, Keycloak (`:8080`) и бэкенд (`:8000`). Без WhatsApp/Claude-оверлея — ключи не нужны.

- `platform/.env` — сгенерированные локальные пароли (в git не попадает).
- Realm `p5i-engineering-demo`, клиент `diploma-frontend`, пользователь `p5i-engineering-owner`; пароль — в `~/.retail-ops-local/p5i.json` (права 600). Там же ID магазина, товара, клиента и заказа.
- `frontend/.env.local` указывает на этот realm и магазин; `P5I_ENABLE_FIXTURE_REVIEW=true`.
- Время жизни токена в realm поднято до 600 с: приложение не обновляет токены, сессия = жизнь токена (максимум 10 минут). После этого — повторный вход в один клик, пока жива SSO-сессия Keycloak (30 минут).

```bash
cd platform
C="docker compose -f infra/compose/compose.yaml -f infra/compose/compose.p5i.yaml --env-file .env"
$C up -d --wait keycloak backend   # запустить
$C stop                             # остановить (данные сохраняются)
python3 -c "import json,os;print(json.load(open(os.path.expanduser('~/.retail-ops-local/p5i.json')))['password'])"  # пароль
```

Известное: в шапке вместо названия магазина — его UUID, потому что `/me` бэкенда возвращает `business_name=None` (так было и до редизайна). Сессии фронтенда живут в памяти — перезапуск `npm run dev` разлогинивает.
