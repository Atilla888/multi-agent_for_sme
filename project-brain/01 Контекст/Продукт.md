# Продукт

## Что строим

**AI-Native Business Operating System для малого и среднего бизнеса (SME)** с фокусом на работу с клиентами и бизнес-аналитику. Домен MVP — **розница и e-commerce**.

Проблема: запросы клиентов приходят в разные каналы, а данные о клиентах, каталоге, заказах, остатках и правилах лежат в разных местах. Сотрудник вручную собирает контекст и делает рутинные проверки. Платформа сводит запросы в один поток: специализированные агенты берут нужный бизнес-контекст, предлагают или выполняют разрешённые действия, а сложные случаи передают человеку вместе с контекстом.

Это **не** универсальный чат-бот и **не** замена CRM/ERP.

## Для кого

| Актор | Что нужно |
|---|---|
| Клиент | Спросить о товаре, наличии, заказе через поддерживаемый канал |
| Оператор / сотрудник | Разбирать эскалации, продолжать диалоги |
| Владелец бизнеса | Смотреть активность, отчёты, прогнозы |
| Администратор | Управлять доступом и настройками |
| Channel Provider | Системный актор (WhatsApp и т. п.), без своего UI |
| Adaptive Orchestrator | Внутренний системный актор; отдельной страницы нет |

## Ключевые понятия

- **Business Brain** — общий контекст из семи частей, а не только RAG. См. [[02 Система/Business Brain и RAG]].
- **Три агента MVP** — Sales, Support, Analytics. См. [[02 Система/Агенты и инструменты]].
- **Ровно десять бизнес-инструментов.** Агент только предлагает действие, а выполняет его доверенный executor.
- **Adaptive orchestrator** — исследовательская цель (RESEARCH TARGET). Алгоритм не зафиксирован.
- **Human handoff** — человек получает проверенные факты, историю действий и причину эскалации.

## Научный вклад

> [!abstract] Исследовательский вопрос
> Улучшает ли **контекстно-зависимая адаптивная мультиагентная оркестрация** результат по сравнению с более простыми схемами при сопоставимых условиях? Вклад — не изобретение агентов, а **экспериментальное сравнение трёх архитектур**: Single Agent, Static Multi-Agent и Context-Aware Adaptive Multi-Agent. Результат заранее не предрешён.

Подробнее — [[03 Исследования/Сравнение архитектур]].

## Границы MVP

- **В scope:** диалоги с клиентами; клиенты, товары, остатки, заказы, продажи; документы и FAQ; три агента; Business Brain; эскалация человеку; аналитика для владельца; модуль прогноза продаж; full-stack приложение.
- **Целевые каналы:** Instagram, WhatsApp, Telegram, Web Chat. Порядок запуска не определён. Реально подключён только демо-канал WhatsApp — см. [[02 Система/Каналы и WhatsApp-демо]].
- **Вне scope:** полный CRM/ERP, дополнительные агенты (Inventory, Marketing, Finance…), Kafka/NATS, ClickHouse, Kubernetes, микросервисы, event sourcing и CQRS без новых оснований.
