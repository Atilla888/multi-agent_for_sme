## Правила разработки (сжато из RULES.md)

- Перед значимой правкой прочитать PRD, ARCHITECTURE, RULES; для UI — ещё DESIGN.
- Статусы писать единым словарём: **IMPLEMENTED**, **PROJECT BASELINE / PLANNED**, **RESEARCH TARGET**, **OPTIONAL / FUTURE**. Диаграмма или план — не доказательство реализации.
- Бизнес-инварианты живут в детерминированных сервисах, а не в промптах или UI. Агент **предлагает**, выполняет только авторизованный executor.
- Неудачное или неизвестное действие никогда не показывать как успех.
- Промпт, найденный документ или ответ модели не могут обойти авторизацию.
- Эксперименты Single / Static / Adaptive — на одних данных, инструментах, сценариях и бюджете. Ground truth и подсчёт фиксируются до просмотра итогов.
- Таблицу Status в README обновлять только по доказательствам: тесты или работающий код.

## Что не коммитить

`.env`, `.env.p2.local`, `.env.local`, `.venv`, ключи провайдеров, INTERNAL-версию master-PDF, `/tmp/p5i-private/p5i.json` с паролем демо-пользователя, данные Ollama и веса моделей.
