# Как вести базу

## Ежедневный цикл

1. Открыть [[00 Старт]] и [[04 Работа/Следующие шаги]].
2. Создать дневную запись через встроенные Daily Notes или по [[99 Шаблоны/Дневная заметка]].
3. После работы обновить профильную заметку и поле `updated`; указать источник и результат проверки.
4. Решение оформить по [[99 Шаблоны/Решение]] и добавить в [[04 Работа/Решения]].
5. Если изменился статус работы, обновить также таблицу **Status** в `README.md` репозитория — она первична.

## Правила памяти

- `snapshot` — прочитанный срез; `proposed` — предложение; `template` — заготовка. Это не статусы готовности продукта.
- Различать: факт из кода, результат из отчёта, собственную проверку и гипотезу.
- У каждой существенной цифры — дата и среда (например, «114/114, P3, 13.10.2026, Docker»).
- Не копировать большие документы целиком: заметка объясняет главное и ссылается на первоисточник.
- При противоречии добавить строку в [[04 Работа/Расхождения источников]].
- Людей называть по GitHub-имени; не записывать e-mail и личные данные.

## Работа с Claude

- В Claude Code подключён плагин `obsidian-skills` (`obsidian-markdown`, `json-canvas`, `obsidian-bases`, `obsidian-cli`, `defuddle`). Для `obsidian-cli` нужно запущенное приложение Obsidian 1.12+ с включённым CLI; на 15.11.2026 Obsidian не установлен.
- После сессии с существенным результатом Claude дописывает дневную запись в `05 Память`, обновляет профильную заметку, [[04 Работа/Решения]] и [[04 Работа/Следующие шаги]].
- У Claude есть и своя память (`~/.claude/projects/…/memory/`) с указателем на эту базу. База — общая память проекта для людей. При расхождении верна более свежая датированная запись.

## Что не записывать

Ключи и токены (Anthropic, Gemini, WhatsApp, Meta app secret), пароли Keycloak и Postgres, содержимое `.env*`, `/tmp/p5i-private/p5i.json`, содержимое INTERNAL master-PDF, номера реальных телефонов из демо.

## Файлы и переносимость

Внутренние ссылки — `[[wikilinks]]` с полным путём от корня базы. Canvas — формат [JSON Canvas 1.0](https://jsoncanvas.org/spec/1.0/). Ссылки на код — абсолютные `file://`, после переноса репозитория их нужно обновить.

`source-manifest.json` хранит SHA-256 исходных файлов, ветку и HEAD на момент среза. Это происхождение среза, а не синхронизация: при новом срезе сверить изменившиеся файлы и обновить манифест.

Папка `project-brain/` исключена из git через `.git/info/exclude`, только в этой рабочей копии. Чтобы публиковать базу вместе с кодом, удалите строку оттуда и закоммитьте папку — `.obsidian/workspace*.json` и кэш уже исключены локальным `.gitignore`.
