# Сравнение архитектур

Главная научная часть проекта. Подробности протокола в проекте ещё **не зафиксированы**.

## Три варианта

| Вариант | Этап | Маршрутизация | Статус |
|---|---|---|---|
| **Single Agent** | M09 `SINGLE` | Один универсальный агент со всеми законными инструментами, без передачи | NOT STARTED |
| **Static Multi-Agent** | M10 `STATIC_MULTI` | Заранее заданная маршрутизация Sales / Support / Analytics | NOT STARTED |
| **Context-Aware Adaptive Multi-Agent** | M11 `ADAPTIVE_MULTI` / LangGraph | Решение «продолжить / уточнить / вызвать инструмент / передать / эскалировать / завершить» в runtime по контексту и состоянию | NOT STARTED |

Все три **заблокированы этапом M08** — живой приёмкой специалистов. Кода экспериментов пока нет: пустая заготовка `platform/experiments/` удалена при чистке 15.11.2026.

## Условия сравнения

- Одни бизнес-данные, проверки безопасности, реализации инструментов, сценарии и правила оценки.
- Сопоставимые бюджеты выполнения. Версионируются сценарии, промпты, модель и настройки, контракты инструментов и код оценки.
- Ground truth и подсчёт фиксируются **до** просмотра итогов; неудачи не отбрасываются.
- Возможные абляции: общий контекст, адаптивная маршрутизация, handoff, структурированное состояние, эскалация по уверенности.

## Кандидаты в метрики

Task Success Rate, Tool Selection Accuracy, Invalid Action Rate, Human Intervention Rate, Latency, Cost per Successful Task, factual grounding / hallucination. Точные формулы, размер бенчмарка и статистический метод — задача будущего протокола.

Для каждого прогона трассировка должна хранить: correlation ID, вариант архитектуры, сценарий и версию, решения агента и маршрутизации, ссылки на контекст, попытки и результаты инструментов, ошибки, эскалацию, задержку, вызовы и расход LLM, итог.

## Прогноз продаж (M13) — отдельно

Качество прогноза оценивается **отдельно** от оркестрации. План: наивный baseline → скользящее среднее → XGBoost при достаточных данных. Метрики MAE, RMSE, MAPE — после определения цели и обработки нулевых знаменателей. LSTM и трансформеры — только с отдельным обоснованием. Кода модели пока нет, ответ системы — `MODEL_NOT_READY`.

## Эксперимент с Ollama

Ветка `experiment/ollama-local` (Erbarak, 13.10.2026): адаптер `agents/ollama.py`, нормализация ответов провайдера и проверка границ безопасности специалистов. Отчёт — `docs/experiments/OLLAMA_LOCAL_EXPERIMENT.md` в этой ветке. По решению P4 это отдельная ветка на отдельном железе; формальную приёмку M08 она **не заменяет**. С 15.11.2026 код в `main` (PR #1); модель — Qwen3 1.7B; через `DEV_LLM_PROVIDER` пока не выбирается.
