# Фронтенд

Next.js 16 (App Router), React 19, TypeScript, Tailwind 4, Vitest. Только npm; источник зависимостей — `package-lock.json`. Node `>=24.12.0 <25`.

> [!warning] Next.js 16
> В `frontend/AGENTS.md` сказано: API и соглашения отличаются от привычных. Перед правкой читать `node_modules/next/dist/docs/`.

## Шесть областей для сотрудников

| Область | Маршруты |
|---|---|
| Overview | `/overview` |
| Conversations | `/conversations`, `/conversations/[id]`, `/escalations` (вложены в Conversations) |
| Business | `/customers`, `/customers/[id]`, `/orders`, `/orders/[id]`, `/products`, `/inventory` |
| Knowledge | `/documents`, `/documents/[id]` |
| Analytics | `/analytics`, `/forecasts` (вложены в Analytics) |
| Administration | `/integrations`, `/settings`, `/audit` (ограничен), `/agent-runs` (контекстный, ограничен) |

Отдельно: `/login` — вход через Keycloak; `/chat` — клиентский Web Chat, mobile-first, пока не настроен.

## Где живые данные, а где фикстуры

- **Живые чтения (P5I):** `GET /me`, `/products`, `/products/{id}`, `/inventory`, `/customers/{id}`, `/orders/{id}`, `/analytics/sales`.
- **Живые с WhatsApp-демо:** `GET /conversations`, `/conversations/{id}` — Inbox.
- **Остальное** — типизированные детерминированные фикстуры с явной пометкой **Sample data**: списки клиентов и заказов, документы, администрирование. Бизнес-мутаций и общего RPC для инструментов в UI нет.
- `?mode=fixture` на любой странице показывает версию с примерами; `P5I_ENABLE_FIXTURE_REVIEW` по умолчанию `false`.

## Авторизация

Keycloak Authorization Code + S256 PKCE. Браузер хранит только непрозрачный HttpOnly-идентификатор сессии, токены остаются на сервере Next.js. Одна Node-инстанция; сессии сбрасываются при перезапуске. Для продакшена нужны HTTPS и общее хранилище сессий. Видимость в UI не заменяет авторизацию на бэкенде.

## Дизайн в коде

С 15.11.2026 (ветка `frontend/redesign`) визуальный слой новый: **светлая тема — тепло folk (CRM для людей), тёмная — точность Linear**. Одна система, тема по ОС, принудительно — `data-theme="light|dark"` на `<html>`.

- **Цвет.** Хром нейтральный: светлая — контент `#ffffff`, сайдбар `#f7f6f3`, текст `#1c1b19`; тёмная — `#101113`, `#0b0c0d`, `#e4e5e7`. Основная кнопка почти чёрная / почти белая. Цвет только в аватарах людей, оранжевой метке магазина (`#d9773a`), иконках статусов и графиках. Без фиолетового, градиентов, blur и цветных теней. Контраст AA проверяется тестами.
- **Шрифт.** Geist 13 px, Geist Mono — для номеров заказов, ID, чисел и времени.
- **Статусы.** Иконка + слова (`StatusIcon`, `StatusBadge`), не заливка. «Needs checking» (исход неизвестен) — пунктирный круг с вопросом, «Failed» — перечёркнутый круг. В плотных строках можно только иконку, метка остаётся для скринридера.
- **Люди и агенты.** Люди — инициалы на одном из шести приглушённых цветов по имени; агенты — нейтральная метка.
- **Структура.** Тонкие линии вместо теней; строки в стиле Linear; факты — в панели деталей справа (`.details-panel`); правило продукта — одна тихая строка `.rule-note`. KPI-карточки и декоративные пояснения убраны.

Статусы по-прежнему один к одному с `src/types/states.ts`. `npm run preview` рендерит все экраны (включая живые — на заглушках) в `.preview/*.html`; `PREVIEW_THEME=dark` — тёмный вариант. Подробно — `docs/DESIGN.md` §6.
