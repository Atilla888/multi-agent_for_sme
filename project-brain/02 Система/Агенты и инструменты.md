# Агенты и инструменты

## Три специалиста

| Агент | Зона | Пример |
|---|---|---|
| **Sales** | Каталог, наличие, покупка и заказ | «Есть настольная лампа?» → `find_product` + `check_inventory` |
| **Support** | Заказы, политики, FAQ, доставка | «Где мой заказ?» → проверка прав → `get_order` |
| **Analytics** | Отчёты и прогнозы для владельца | «Сводка продаж за месяц» → `get_sales_report` |

Код — `platform/services/backend/src/platform_backend/agents/`: `runtime.py` (общий runtime специалистов), `provider.py` (LLM-адаптеры), `prompts.py` (версионированные промпты), `contracts.py` (типизированные решения).

## Ровно десять инструментов

`find_product`, `check_inventory`, `find_customer`, `get_order`, `create_order`, `update_order`, `reserve_inventory`, `get_delivery_status`, `get_sales_report`, `forecast_sales`.

Это закрытый реестр M04: строгие схемы, матрица прав агент × инструмент, типы эффектов и ошибок. Добавлять инструменты без отдельного решения нельзя.

## Как выполняется действие

1. Модель **только предлагает** вызов инструмента.
2. `tools/executor.py` независимо проверяет принципала, арендатора, схему входа, бизнес-правила и состояние.
3. Запись выполняется только после явного подтверждения клиента — в WhatsApp-демо это ответ **YES**.
4. Результат и попытка пишутся в аудит с correlation ID.

> [!danger] Инварианты, которые нельзя ломать
> - **E02:** мутация `update_order` заблокирована политикой (`BLOCKED_BY_APPROVED_POLICY`). Sales не меняет заказ, а передаёт решение человеку с контекстом.
> - **`OUTCOME_UNKNOWN`:** запись могла пройти. Показывать «ожидает сверки», а не успех или откат; **слепой повтор запрещён**.
> - `create_order` ≠ `reserve_inventory`: заказ может существовать без подтверждённого резерва. У каждого эффекта свой статус.
> - Ошибка доставки сообщения не отменяет подтверждённый бизнес-эффект.
> - `forecast_sales` возвращает `MODEL_NOT_READY`, пока нет проверенной модели M13. Прогнозы не выдумываются.
> - Передача Support → Sales не расширяет права.

## LLM-провайдеры

| Провайдер | Модель по умолчанию | Где включён |
|---|---|---|
| Gemini (REST `generateContent`, без SDK) | `gemini-3.8-flash` | `compose.yaml`, значение по умолчанию в `provider.py` |
| Claude | `claude-opus-5-5` | `compose.demo.yaml`, `.env.example` |
| Ollama (эксперимент) | Qwen3 1.7B | В `main` с 15.11.2026 (PR #1): `agents/ollama.py` (`OllamaProvider`), тесты, `docs/experiments/OLLAMA_LOCAL_EXPERIMENT.md`. Через `DEV_LLM_PROVIDER` **не выбирается**: в `SUPPORTED_PROVIDERS` только gemini и claude |

Переключение — переменные `DEV_LLM_PROVIDER` и `DEV_LLM_MODEL`; ключи — `ANTHROPIC_API_KEY` и `GEMINI_API_KEY`, только из окружения. Повторяемость вывода модели (seed) не проверена. По `P4`-решению Ollama не заменяет и не закрывает приёмку M08.
