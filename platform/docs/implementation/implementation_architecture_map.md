# Implementation-visible architecture map

The six approved macro-layers remain Client Channels → API Gateway & Security → Adaptive Orchestration → Business Brain → Tools / Operational ML → Data & Infrastructure. M03–M05 implement the trusted domain/tool/identity core; M06 implements typed, read-only Business Brain assembly; M07 supplies its private, tenant-scoped knowledge subsystem. M08 adds a partial specialist runtime; no architecture treatment orchestrator exists yet.

Trusted flow: typed input + server-owned `ExecutionContext` → tool schema/agent permission → principal/resource policy → domain service → tenant-bound repository → PostgreSQL/RLS → durable result/audit. Model-visible arguments cannot supply the business scope or principal. M08 model proposals enter only above this boundary; real-provider execution is not yet validated.

The M07 checkpoint above is historical. M08 is now authorized and partially implemented: `agents/contracts.py` defines typed untrusted proposals/outcomes, `agents/prompts.py` holds versioned DEVELOPMENT shared/specialist prompts, `agents/provider.py` contains a bounded Gemini REST adapter, and `agents/runtime.py` composes the same Business Brain and trusted ToolExecutor for exactly Sales, Support and Analytics. Model proposals never carry trusted principal/business scope. Server-owned write confirmation and stable operation keys gate effects. Runtime trace events are in-memory at this stage, not a durable M11/M12 checkpoint. M08 is **BLOCKED** pending real-provider validation; M09–M12 have not started because of the M08 gate. No SINGLE, STATIC_MULTI, ADAPTIVE_MULTI, LangGraph, HITL persistence, forecast training, Pilot or Final behavior is claimed. The `update_order` mutation branch remains policy-gated, not silently implemented.
